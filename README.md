# 一箭又一箭 · Arrow After Arrow

Python 3 + Pygame 的点击解谜小游戏。深色主题，1000x600，单文件实现，
**关卡模式 + 无尽模式 + 速度模式**，带**提示 / 撤销**和**拓展 · 创意工坊**，最佳记录存在本地。

---

## 一、核心玩法

棋盘上的每个箭头都是一条**有长度、内部还能拐弯**的折线（箭尾 → 箭头），长得像 `→` 或 `↳`。

点击一支箭头：

1. 看它**箭头前方**那条射线上有没有别的箭头；
2. **没有阻挡** → **本体**沿着自己的轨道飞出棋盘并消失；
3. **有阻挡** → **本体**先沿轨道冲过去、撞在被挡的那一格上，再阻尼弹回原位
   （被撞的格子标红、接触点闪白光），同时失误次数 -1；
4. 清空本关所有箭头 → 通关；失误次数用完 → 失败。

> **悬停不会告诉你哪支箭能飞。** 鼠标移上去只有一圈**中性灰色描边**，
> 表示"我指的是这一支"。早先那版会用绿框/红框预告能不能走，结果玩家只要看颜色就行、
> 谜题直接失效，所以已经去掉了。想看答案请用**提示**功能（有限次数）。

## 二、三种玩法

| 模式 | 规则 | 结束条件 | 记录 |
| --- | --- | --- | --- |
| **关卡模式** | 3 个关卡逐关推进 | 通关 / 失误用尽 | 已通关数量 |
| **无尽模式** | 随机关卡，一关比一关大 | 失误用尽 → **整局结束** | 最多通过几关 |
| **速度模式** | 60 秒内尽可能多通过机关，失误一次 **-3 秒** | 时间到 | 最多通过几道 |

* **无尽模式**要通过关卡模式全部 3 关才解锁（首页按钮会灰掉并提示条件）。
* **无尽模式失败后不能从那一关重来**：失败界面是「本局结束」，
  只能「再开一局（从第 1 关）」或者回主菜单 —— 成绩当场写进最佳记录。
* **速度模式**固定用 6x6 的棋盘保证节奏一致，通过一道立刻换下一道、计时不停。

## 三、提示与撤销

### 提示（H）

遍历盘面找一支 **`neighbor(朝向) == None`** 也就是**现在就能安全飞出去**的箭头，
给它套一圈会呼吸的金色描边，2.6 秒后自动消失（被点掉或者飞走了也会立刻取消）。

```python
def pick_flyable(self):
    candidates = [one for one in self.arrows
                  if not one.flying and self.can_fly(one)]
    return random.choice(candidates) if candidates else None
```

### 撤销（U / Z）

**关键点：不能只把箭头放回原位。** 邻居图是从箭头列表重建出来的，
箭头飞走后那些格子已经从链上摘掉了，只恢复坐标的话图就是错的。

这里采用「**只记最初那张图 + 玩家点过的顺序**」的做法（不用每步深拷贝快照，
也不用维护邻居变更日志）：

```python
def replay(self, history):
    self.load_level(self.source)          # 最初那张图（load_level 里存下来的）
    for (row, col, _was_blocked) in history:
        self.click_cell(row, col, animate=False)   # 安静地重放剩下的操作
```

`history` 里存的是 `(行, 列, 是否撞击)`，因为撤销时还要：
* 把那次**撞击的失误数**一起回滚（重放 blocked 操作会自然加回来，所以直接重放前缀即可）；
* 速度模式里把那次撞击扣掉的 **3 秒退还**回去。

撤销后箭头位置、邻居关系、失误数、点击数全部回到"当时那个局面" ——
自检第 16 项会拿 `signature()`（每支箭的格子+朝向、失误、点击数、邻居图格子数）
和**直接重新载入本关**的结果逐项比对。

### 次数限制

| 模式 | 提示 | 撤销 |
| --- | --- | --- |
| 关卡模式 | 不限 | 不限 |
| 无尽模式 | 每局 3 次 | 每局 3 次 |
| 速度模式 | 每局 2 次 | 每局 2 次 |

按钮上直接显示剩余次数，用完就变灰；按 R 重开本关**不会**刷新次数（防刷）。
两个功能都可以在「拓展 · 创意工坊」里整个**停用**（见下一节），停用后按键无效。

## 四、拓展 · 创意工坊

首页第三排的「拓展 · 创意工坊」按钮进去是一个独立界面（`STATE_WORKSHOP`），
分成**「功能」**和**「地图」**两个页签。

### 4.1 功能页：可开关的拓展

* 卡片上只写**怎么用**（按键 + 一句话说明），不写内部是怎么实现的；
* 右边一个胶囊开关，点开关或点卡片任意位置都能切换，卡片描边和"已开启 / 已关闭"同步；
* 开关状态写进 `save.json`，下次启动仍然生效；
* 停用之后，游戏中按对应按键没有任何反应，底部按钮会显示成「已关」并变灰。

现在有三个功能：**提示**、**撤销**、**音效**（前两个见上一节）。

**音效**（`SoundKit`）不是外部素材文件，而是用 `pygame.mixer` + 标准库 `array`
**现场合成波形**（`build_wave()`），所以拷到哪都能出声。两套音色可选，选完立刻试听：

| 音色 | 飞出 | 撞击 |
| --- | --- | --- |
| 电子 `electronic` | 上滑的方波短音（峰值 ≈ 9.7k） | 下坠的锯齿短音（峰值 ≈ 29.6k，**3.1 倍**） |
| 木质 `wood` | 清脆的正弦"叮"（峰值 ≈ 8.3k） | 低沉的"咚"（峰值 ≈ 27.7k，**3.3 倍**） |

撞击音刻意做得比飞出音响得多（要求 ≥1.8 倍，自检会卡这条），
这样不看画面也能从声音判断"这一下撞了"。

拿不到音频设备时（无声卡环境、CI）自动降级成静音，游戏照常玩。
播放点在场景的事件处理里（`Game.play_sound()`），所以**撤销重放不会出声**。

卡片由 `FEATURES` 登记表生成，加一个新功能是三步：
① `FEATURES` 里加一条 → ② `PlayingScene` 里接上行为 → ③ `Records` 里加个 `xxx_on` 字段。

### 4.2 地图页：玩家自己上传地图

**上传方式就是把 `.json` 文件放进 `maps/` 目录**，工坊每次进来都会重新扫描：

* 左边列出找到的地图（名称 / 尺寸 / 箭头数 / **可解性**），点一行选中，再点「开始游戏」直接试玩；
* 每张图都会**现场校验**：格式错、越界、重叠、箭身断开都会把原因显示在条目上（红色），坏文件不会让游戏崩；
* **自己试玩通关过的图会标上「已通关」**：这张图不仅"算出来可解"，而且"真人真解开过"。
  标记按地图内容的指纹存进 `save.json`，改了文件就自动失效，不会出现"改完还是已通关"的假象；
* 右边贴着格式说明和 `maps/` 的真实路径；
* 「生成示例地图」按钮会把 `示例地图.json` 写进目录，照它改就行；
* 选中自定义地图开玩时，HUD 显示「自定义地图 + 地图名」，提示/撤销**不限次数**（自己的图不用卡），
  通关后可以直接「返回创意工坊」挑下一张。

地图文件长这样（箭头有两种写法，`direction` 能省就省）：

```json
{
  "name": "我的地图", "author": "谁", "rows": 6, "cols": 6, "max_mistakes": 3,
  "arrows": [
    {"row": 0, "col": 0, "length": 6, "direction": "right"},
    {"cells": [[1,1], [1,2], [1,3], [2,3]]}
  ]
}
```

* `{"row","col","length","direction"}`：直线箭头的简写，`(row, col)` 是**箭尾**；
* `{"cells": [[r,c], ...]}`：折线箭头，按顺序从箭尾走到箭头，**朝向自动取最后一段**；
* `rows` / `cols` 可以省，按箭头占的格子自动推算；上限 12x12（再大格子就太小了）。

仓库里已经放了一张 `maps/示例地图.json`（6x6 / 7 支 / 可解）当模板。

### 4.3 这个工坊的"可扩展性"到底是什么水平

说实话，两半的成色不一样：

| | 现状 | 加东西要改什么 |
| --- | --- | --- |
| **功能** | **配置化，不是插件化**：卡片由 `FEATURES` 表生成，但功能行为仍写死在 `PlayingScene` 里 | 改 3 处代码（表 / 行为 / 存档字段），玩家不能自己加 |
| **地图** | **真的可上传**：文件驱动，玩家不碰代码就能加内容；有校验、可解性检查、试玩闭环 | 玩家只需要往 `maps/` 丢 json |

也就是说：**地图是真扩展，功能只是个带开关的固定集合**。
要做成真正的插件式（第三方功能脚本、地图带自定义规则）需要引入"功能清单 → 注册钩子 → 动态加载"，
现在没做，这里如实写清楚，免得看起来像个插件系统。

### 4.4 为什么没做"可视化地图编辑器"

曾经考虑过在工坊里直接画地图（拖格子、放箭头、必须自己试玩通关才能保存）。**评估后决定不做**，
理由是工作量对不上，这里把账摊开：

| | 行数（实测） |
| --- | --- |
| 整个游戏 `arrow_puzzle.py` | 3758 |
| 其中界面层（Scene 1028 + 绘制工具 165） | ≈ 1193 |
| 其中工坊现状（工坊 Scene ≈ 260 + 地图数据层 245） | ≈ 505 |
| **一个可用编辑器（估算）** | **≈ 800 ~ 1000** |

估算拆开是：编辑器界面 ≈400 行（网格绘制、鼠标→格子换算、笔刷面板、箭头列表、实时校验提示、工具栏）
+ 编辑态数据模型 ≈150 行（新增/删除/旋转/改尺寸，以及**编辑器自己的**撤销栈）
+ "必须试玩通关才能保存"的往返与标记 ≈60 行 + 状态机与 HUD 接线 ≈80 行 + 自检 ≈100 行。

换算下来它**比现有的任何单一子系统都大**（约等于整个界面层的 70%~85%、工坊现状的 1.6~2 倍），
而且风险最集中：鼠标拖拽、**必须允许存在的非法中间态**（编到一半时重叠/越界/断开都是正常的）、
编辑撤销与游戏撤销是两套东西、尺寸变更、以及"编辑器→试玩→回到编辑器"的状态保持。

所以按"接近甚至超过本体就不搞"的规则：**不做**。
只把其中**便宜的那一半**做了 —— 「自己试玩通关过的图会标上「已通关」」（≈40 行）：
它给的是同样的信任信号（这张图真人解开过），代价却只有编辑器的 1/20。

## 五、运行

```bash
cd arrow_puzzle
python arrow_puzzle.py                # 从第 1 关开始
python arrow_puzzle.py --level 2      # 直接从第 3 关开始（下标从 0 起）
python arrow_puzzle.py --endless      # 直接进无尽模式
python arrow_puzzle.py --speed        # 直接进速度模式
python arrow_puzzle.py --selftest     # 无窗口自检（22 项）
python run_tests.py                   # 验收用例 T01~T09（无窗口，用临时存档）
```

`run_tests.py` 按验收清单逐条驱动真实游戏对象（鼠标/键盘都走真实事件），
测完打印结果表和每条用例的实测数据；测试过程与结论记在
[`BLOG_测试记录.md`](BLOG_测试记录.md)。

依赖只有 pygame。`vendor/` 里内置了兼容 Python 3.7 的 **pygame 2.1.2**，自动加载。

### 打包成可执行文件

```bash
python build_exe.py              # 默认 onedir -> dist/ArrowAfterArrow/ArrowAfterArrow.exe
python build_exe.py --onefile    # 打成单文件 exe（需要 %TEMP% 可写）
```

* PyInstaller 没装的话，脚本会自己 `pip install --target build_tools`，不动系统环境；
* 游戏**不依赖任何素材文件**（字体走系统、音效是现场合成的波形、地图是纯文本），
  所以打包不需要 `--add-data`，整个包只有 pygame 那一坨（onedir 约 19.7 MB）；
* 存档 `save.json` 和 `maps/` 都在 **exe 旁边**（`_HERE` 在冻结模式下取 `sys.executable` 的目录），
  整个文件夹拷走，进度和地图都跟着走；

**为什么默认 onedir**：onefile 每次启动都要把 pygame/SDL 解包到系统临时目录，
启动慢，而且在写不了 `%TEMP%` 的受限环境（或被杀软拦）会直接起不来——
实测报错 `Failed to extract SDL2.dll: fopen: Permission denied`。onedir 没有这一步。

打完包之后，`exe --selftest` 可以再跑一遍 22 项自检（`--windowed` 没有控制台，
报告会写到 exe 旁边的 `selftest_report.txt`），退出码 0 就是全过。

### 分发什么（实测过）

| 方案 | 能不能跑 | 说明 |
| --- | --- | --- |
| 只拷 `ArrowAfterArrow.exe` | ❌ **不能** | exe 只是个入口，依赖同目录的 dll。实测：8 秒不退出、连自检报告都没生成（Python 都没起来） |
| **整个 `dist/ArrowAfterArrow/` 文件夹** | ✅ **可以** | 换到别的路径、删掉 `maps/` 都能跑（退出码 0，22 项全过） |
| 整个 `arrow_puzzle/` 项目文件夹 | ✅ 可以但没必要 | 源码、`vendor/`、`build_tools/`、测试都不是运行必需品 |

**结论：发 `dist/ArrowAfterArrow/` 这个文件夹（或者 `dist/ArrowAfterArrow.zip`，8.9 MB）。**

* 解压后 19.7 MB / 104 个文件：62 个 dll（14.2 MB）+ 10 个 pyd（1.9 MB）+ exe（1.5 MB）
  + `base_library.zip` + `pygame/`（1.2 MB，pygame 自己的扩展和字体数据）+ `maps/`；
* **目标机器不需要装 Python，也不需要装 pygame**：`python37.dll`、`SDL2*.dll` 都在包里；
* `maps/` 可以不带，第一次运行会自动重建并放一张示例地图；
* 存档 `save.json` 玩过一局破了纪录才生成，位置也在 exe 旁边；
* 文件夹可以整体拷到别的机器/别的目录，路径无关（实测换路径后正常运行）。

## 七、箭是怎么动的：沿轨道走，不是整体刚性平移

```
轨道 = [箭身自己的格子] + [箭头前方延长出去的格子]
前进 offset 格 = 把箭身放到轨道上 offset ~ offset+length-1 这一段
```

画面上就是**头部先沿着朝向直行、后面的拐弯一点点被拉直**（像火车沿铁轨开出去）。
由此还带来判定上的简化：**每一步只有箭头那一格会进入新格子**，所以能不能飞只看箭头正前方：

```python
def can_fly(self, one):
    if one.flying:
        return False
    return self._nearest_other(one.head, one.direction, one) is None
```

### 动画期间动的是"本体"，不会留幻影

```python
class Arrow:
    offset = 0.0     # 沿自己的轨道前进了多少格（0 = 停在原地）
    flying = False   # 已脱离占用表/邻居图，但对象还在画
    anim   = None    # FlyOutAnim / BounceAnim
```

* **弹回**：`BounceAnim` 把 offset 从 0 推到 `travel`，再阻尼振荡回 0
  （弹回会过冲成负值，所以轨道**前后都要延长**，否则负下标会让图形画到离谱的位置）；
* **飞出**：`_launch()` 让本体立刻脱离占用表和邻居图，但对象留在 `self.arrows` 里
  沿轨道飞出棋盘，**飞完才回收**；撤销回放时用 `animate=False` 让它直接消失。

通关要等最后一支箭飞出去（`board.win_ready`，缓冲 0.55s；速度模式 0.20s）。

## 八、关卡数据：箭头对象列表

```python
def arrow(row, col, length, direction):
    """直线箭头：(row, col) 是箭尾格子，沿 direction 伸 length 格。"""

def poly(cells):
    """折线箭头（内部可以拐弯）：按给定格子从箭尾走到箭头，朝向取最后一段。"""
```

两个函数都只是生成 `{"cells": [...], "direction": ...}`：

```python
LEVELS = [
    {"name": "第 2 关 · 环环相扣", "rows": 6, "cols": 6, "max_mistakes": 3,
     "arrows": [
         arrow(0, 0, 4, DIR_RIGHT),                       # 直线
         poly([(4, 1), (5, 1), (5, 2), (5, 3), (5, 4)]),  # 先往下再往右的拐弯箭头
     ]},
]
```

载入流程：`load_level()` → 解析路径 / 推导朝向 → 校验 → 新建全部 `Arrow` →
**`rebuild_neighbors()` 建图** → 分配颜色 → 按行列数自动缩放格子。
校验会检查**越界 / 重叠 / 同一支箭重复占格 / 箭身断开 / 方向与最后一段不一致**。

| 关卡 | 棋盘 | 箭头 | 拐弯 | 特点 |
| --- | --- | --- | --- | --- |
| 第 1 关 · 热身 | 6x6 | 6 支 | 0 | 全直线，只有一处先后依赖 |
| 第 2 关 · 环环相扣 | 6x6 | 8 支 | 1 | 摆成「回」字，先拆外圈；引入拐弯箭头 |
| 第 3 关 · 密林 | 8x8 | 13 支 | 7 | 密集蛇形折线，需要推演清除顺序 |

### 随机关卡怎么保证一定可解（无尽 / 速度模式）

> 设清除顺序是 a1, a2, ..., an（a1 先飞走）。ai 能飞的条件是「那一刻它箭头前方没有活着的箭头」。
> 于是**倒着摆**：先摆 an，再摆 a(n-1) …… 最后摆 a1。摆 ai 时棋盘上正好只有 a(i+1)...an，
> 所以只要"此刻箭头前方这条射线是空的"就行。

无尽模式难度曲线 `endless_config(stage)`：6x6 → 7x7 → 8x8，箭最长 4 → 6 格，越来越密。

## 十、棋盘数据结构：单元格邻居图

```python
class CellNode:            # 一个被占用的格子
    __slots__ = ("row", "col", "owner", "neighbors")
```

`Board.rebuild_neighbors()` 一次性建好整张图（行内左右串联、列内上下串联）。
判定就是沿邻居链走几步：

```python
def _nearest_other(self, cell, direction, owner):
    """沿邻居链找第一个"不属于 owner"的占用格子（跳过自己的箭身）。"""
    node = self.cells[cell].neighbors[direction]
    while node is not None and node.owner is owner:
        node = node.neighbors[direction]
    return node
```

一支箭飞出后，把它**每个**格子逐个拆链（上下对接、左右对接）。
朝向与增量全文件只保留**一份** `DIR_STEPS`（行增量, 列增量），规则判定和图形绘制共用它。

## 十四、自检覆盖了什么

`python arrow_puzzle.py --selftest` 跑 22 项（用临时存档，不会碰你自己的 `save.json`）：

1. 每支箭的图形朝向都与数据方向一致（整关渲染逐支核对"头格前缘比后缘窄"）
2. 3 个关卡结构合法（越界/重叠/重复占格/箭身断开），统计拐弯箭头数量
3. 3 个关卡全部可解
4. **移动规则与邻居图 始终和几何扫描一致**：每关一路拆到清空、每拆一步交叉验证
   `can_fly()` vs `head_ray_can_fly()`，外加 45 个随机关，共 75 次校验
5. 重新开始会重建全部箭头与邻居图，无旧引用残留
6. **悬停只有中性描边**：悬停时红/绿像素为 0，且"能飞"与"被挡"的悬停外观按格平均像素一致
7. 首页「开始游戏」→ 关卡模式第 1 关
8. **有阻挡时"本体"真的在动**：撞点计算正确；推到最远处渲染，原箭尾格同色像素 **967 → 0**；
   整段弹回里画出的点都在合理范围（覆盖过冲负位移），结束时 offset 精确归零
9. 无阻挡 → 本体飞出棋盘（对象仍在、已脱离子棋盘），飞完才回收
10. 关卡模式 第 1 → 第 2 → 第 3 关 逐关推进
11. 三关全通 → 解锁无尽模式，记录落盘（重新读文件核对）
12. 无尽模式失败 → 整局结束（只能从第 1 关开新局），成绩写入记录
13. 速度模式：倒计时、失误 -3 秒、通过一道立刻换下一道、时间到结算并记录（重读存档核对）
14. 首页读取并显示最佳记录
15. **提示**：高亮的那支箭一定 `can_fly()`；高亮真的画出来了；到时间会自己消失
16. **撤销**：点两次（一次飞出 + 一次撞击）后逐步撤销，
    每一步都和"一步之前"的签名一致；撤到底等于**重新载入本关**；
    邻居图 rebuilt（`verify_neighbors` 通过）、失误数回滚、没历史时不能再撤
17. **次数限制**：无尽 3/3、速度 2/2、关卡不限；用完就拒绝；
    速度模式撤销撞击会把扣掉的 3 秒还回来
18. **创意工坊的开关**：关掉提示后按 H / 点按钮都没反应且不产生高亮；
    关掉撤销后有历史也撤不动、历史不被改动；重新打开就恢复；
    开关会写进 `save.json`（重读文件核对）；工坊界面带着两个开关画得出来
19. **音效**：两套音色各两种音效、可切换可关闭，点击时真的会播
20. **地图**：示例地图可解、`rows/cols` 自动推算、折线方向自动取最后一段；
    7 种格式错误和 3 种几何错误（越界 / 重叠 / 箭身断开）都报 `ValueError`；
    目录里塞一个坏 json，扫描会把它标成错误而不是崩掉
21. **自定义地图模式**：能加载（7 支）、提示 / 撤销不限次数、通关后盖上「已通关」并落盘、
    改动地图后标记自动失效、能回创意工坊；两个页签都能画
22. 六个界面绘制正常

第 4 项是关键护栏（两套独立实现互校），第 6/8 项是"不许泄漏答案"和"不许出现幻影"的硬约束，
第 16 项是"撤销必须还原整张邻居图"的硬约束，第 18 项盯的是"拓展功能的开关真的能关掉功能"，
第 20/21 项盯的是"玩家丢进来的地图不能把游戏搞崩"。
